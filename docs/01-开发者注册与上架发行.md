# 开发者注册与上架发行

从注册个人开发者到应用上架的全流程。**结论先行：个人开发者可以注册、可以上架，注册与实名认证免费，无年费**
（不像 Apple 有 99 美元/年年费）。但有若干能力和类目对个人不开放，详见[备案与资质要求](备案与资质要求.md)。

## 一、注册与实名认证

### 流程

```
1. 注册华为账号（手机号或邮箱）
        |
        v
2. 用该账号登录华为开发者联盟
        |
        v
3. 选择「个人开发者」身份，完成实名认证
        |
        v
4. 同意《华为开发者服务协议》等协议
        |
        v
5. 获得开发者资格，可创建应用 / 申请证书
```

官方说明：开发者需先注册华为开发者联盟账号，并完成实名认证，方可使用更多联盟功能与服务资源；
**只有实名认证过的开发者才允许进行应用上架分发。**

### 实名认证方式

- 人脸识别验证；或
- 填写中国大陆身份信息 / 银行卡验证。

入口：华为账号 → 个人信息 / 账号安全 → 实名认证 → 去实名。

### 需要准备的材料（个人）

- 姓名、地址、联系电话、邮箱
- 身份证号、身份证正反面照片、证件有效期
- 手持证件照片
- 开发者信息、华为账号信息、用户名/昵称、第三方账号信息、工作信息

另有一条容易漏的：上架提交资质时，**个人开发者需要同时提供「个人开发者承诺函」**（官方提供模板）。

### 注册条件

| 条件 | 说明 |
| --- | --- |
| 年龄 / 行为能力 | 需具备完全民事行为能力，实操口径为年满 18 周岁 |
| 实名 | 必须使用真实身份信息，平台依《网络安全法》等做网络实名制 |
| 主体地区 | 中国大陆主体用大陆身份证；**港澳台及海外个人主体一般不能注册中国大陆开发者联盟账号**（这条来自第三方整理，未在官方文档直接确认），需走华为海外站点 |
| 账号归属 | 一个华为账号对应一个开发者身份；企业和个人不要混用同一账号 |

### 费用

- 注册华为账号、开发者联盟实名认证：**无收费项**
- 上架分发：**无上架费、无年费**
- 真正会产生费用的地方：
  - 应用内支付 / 广告的收入分成
  - 云服务、云测试、云调试等增值服务
  - 软著加急、电子版权认证等第三方服务（不是华为收的）

### 常见坑

1. **一开始就用个人手机号注册了企业开发者账号**，导致账号信息和企业信息绑定，后续无法拆分。
   官方建议企业开发者一开始就用企业公共邮箱/手机号注册。
2. **身份证照片不规范**：需原件拍照或彩色扫描，不可隔屏拍摄，边角完整、内容清晰、无反光，水印只能一行且不遮挡重要信息。
3. **误以为注册了就能上架**：实名认证只是第一步，APP 备案、资质、签名证书都还要各自走流程。

## 三、签名体系（和 Android 差别很大）

鸿蒙生态**从开发阶段就要求申请开发者证书**，且：

- **调试阶段要在 AGC 做三件事**：申请调试证书、注册调试设备、申请调试 Profile，然后才能配置签名。
  设备白名单落在 **Profile（`.p7b`）** 里 —— 证书本身不绑设备，**"绑设备"的是 Profile + 注册设备列表**。
  官方原文见 `开发指南/Screen_Time_Guard_Kit_屏幕时间守护服务/开发准备/配置签名/screentimeguard-app-signature`。
  白名单外的设备装不上调试包，报的是签名/权限类错误，很容易误判成构建问题。
- **发布时必须用发布证书 + 发布 Profile 重新签名后上传**，保证开发者可溯源。
  注意"发布"不是"把调试包换个地方传"—— 证书和 Profile 都要重新申请。
- 应用上架后平台还会做安全隐私检测、审核、代码签名、应用加密。

证书申请在 AGC 里进行，通常需要先生成密钥（`.p12`）、证书请求文件（`.csr`），
再申请证书（`.cer`）和 Profile（`.p7b`）。

**DevEco Studio 有向导可以自动完成这套流程**；纯命令行用 `devecocli auth login` + `devecocli signature generate`，
但 CLI 路径下"先在 AGC 注册调试设备"这一步**不能省**（CLI 的设备预检会硬停，
见 [工具链 / 环境搭建](toolchain/01-环境搭建.md) 的"签名"坑 0）。

> ⚠️ **换签名 = 清数据。** 签名身份变了，应用会被当成全新安装，`/data/app/el2/100/base/<包名>` 的 uid 变化，
> `preferences` 全丢。多机开发要共用同一套 `p12` + `p7b`。

## 四、上架步骤

1. **AGC 创建应用**：填写应用名称、包名（bundleName）、应用分类、默认语言。
2. **配置应用信息**：图标、截图、简介、隐私政策链接、权限说明、分发国家/地区、付费情况、内容分级问卷。
3. **上传软件包**：DevEco Studio 打包，选择 `.app` / HAP 上传。
4. **填写资质文件**：软著、备案号、行业资质（视品类）。
5. **提交审核**。
6. **审核通过后发布**：可全量发布，也可分阶段发布。

### 测试轨道

正式发布前可以先用测试轨道收集反馈：

- **邀请测试**：挑选特定用户群组，上传测试包并填写测试信息；
- **公开测试**：向 AppGallery 用户公开发布测试版本。

AGC 还提供接入自检、云测试、云调试，可以提前发现兼容性/性能问题，减少正式审核被驳回的概率。

## 五、审核

- 审核依据《华为应用市场审核指南》与《应用资质审核要求》，两者都在持续更新。
- 常见驳回集中在：APP 备案缺失或名称不一致、软著缺失或名称不一致、隐私政策不合规、
  第三方 SDK 未明示、权限申请与功能不匹配、内容分级不实、截图/描述与实际功能不符。
- 支持催审、1v1 专家沟通等服务。

## 六、名称一致性（高频踩坑）

以下三个名称**必须一致**，否则会被驳回，且修改任何一方都要联动变更：

```
应用在商店的名称  ==  软著登记名称  ==  APP 备案名称
```

如果确实要改名，需要**先变更备案信息、更新软著，再提交上架**。

同理，**`bundleName` 定了就不要改** —— 它和 APP 备案、软著登记名称强绑定。
