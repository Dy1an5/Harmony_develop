# 01 环境搭建（Linux，不装 DevEco Studio）

本机（Linux）把鸿蒙工具链装起来、签上名、能跑模拟器的完整过程。**内容都是本机实测过的。**

## 结论

**不是必须装 DevEco Studio。** DevEco Studio 官方提供 **Windows / macOS / 鸿蒙电脑（HarmonyOS PC）** 三个平台，
**没有 Linux 版**；但官方把整套工具链拆出了一个 **Command Line Tools（CLT）** 包，**有 Linux 版**，
官方文档还专门写了 `macOS/Linux` 的配置章节。

| 平台 | DevEco Studio | Command Line Tools | 最低版本 |
| --- | --- | --- | --- |
| Windows | 支持 | 可选 | Studio 6.0.0 / CLT 26.0.0 |
| macOS | 支持 | 可选 | 同上 |
| 鸿蒙电脑（HarmonyOS PC） | 支持（要求 HarmonyOS 7.0+） | 可选 | 同上 |
| Linux | **不支持** | **必选** | CLT 26.0.0 |

> 上表是综合官方各篇安装文档整理的，**不是某一篇的逐字引用**。出处：
> `开发指南/开发环境搭建/下载与安装DevEco_Studio/ide-software-install`（「DevEco Studio支持Windows和macOS系统」）、
> `.../ide-hmos-software-install`（鸿蒙电脑要求 HarmonyOS 7.0 及以上）。

也就是说：Linux 上不是"不能开发鸿蒙"，而是"**必须显式告诉工具链工具在哪**"（因为没有 Studio，只有 CLT）。

## 一、官方 Command Line Tools

### CLT 里有什么

> CLT 集合了 HarmonyOS 应用开发所用的系列工具，包括代码检查 `codelinter`、堆栈解析 `hstack`、命令行构建 `hvigorw`、
> 三方依赖管理 `ohpm`，以及 SDK 中包含的一系列工具（含设备调试工具 `hdc`）。
> **HarmonyOS SDK 已嵌入命令行工具中，无需额外下载配置。**

### 前置依赖

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| JDK | **21** | 官方原文：CLT ≥ 26.0.0 **推荐 JDK 21**；26.0.0 以下推荐 JDK 17 |
| Node.js | ≥ 22 | hvigor / ohpm 运行时。官方建议直接用 CLT 自带的 `tool/node`（`$CLT_HOME/tool/node/bin`） |
| Command Line Tools | ≥ 26.0.0（Linux x64） | 下载中心选 Linux 版 |

系统平台要求：

| 项 | 要求 |
| --- | --- |
| 操作系统 | Linux 64 位 |
| GLIBC | **≥ 2.28** |
| 内存 | 推荐 16 GB 及以上，最小 8 GB |
| 硬盘 | 100 GB 及以上 |

### 步骤

1. 到下载中心取 Command Line Tools：https://developer.huawei.com/consumer/cn/download/command-line-tools-for-hmos
   选 **Linux** 版，按页面"工具完整性"指引做校验。
2. 解压到任意目录，例如 `~/harmonyos/command-line-tools`。
3. 配置环境变量：

```bash
echo 'export PATH=$HOME/harmonyos/command-line-tools/bin:$PATH' >> ~/.zshrc
source ~/.zshrc
codelinter -v                     # 验证
```

4. `hdc`（设备调试，类比 adb）在 SDK 的 toolchains 目录下，要单独加进 PATH：

```bash
export DEVECO_SDK_HOME=$HOME/harmonyos/command-line-tools/sdk
export HDC_HOME=$DEVECO_SDK_HOME/default/openharmony/toolchains
export PATH=$HDC_HOME:$PATH
hdc list targets
```

5. **本仓库把它封装成了 `scripts/env.sh`**，`source` 一下即可，PATH 是幂等的（重复 source 不会重复追加）：

```bash
source scripts/env.sh
```

### 常用命令速查

```bash
hvigorw --version                      # 构建工具版本
hvigorw assembleHap -p buildMode=debug # 打 debug HAP
hvigorw assembleApp                    # 打 .app（上架用）
hvigorw clean --no-daemon

ohpm install                           # 装依赖（类比 npm install）
ohpm list

hdc list targets                       # 看设备
hdc install entry-default-signed.hap   # 装应用
hdc shell                              # 进设备 shell
hdc hilog                              # 看日志

codelinter                             # 代码检查
```

> `hvigorw` 大部分命令要在**工程根目录**下执行；`-v/--version/-h` 这类可任意路径执行。CI 里建议加 `--no-daemon`。

## 二、DevEco CLI（更省事，本机在用）

DevEco CLI 把 `ohpm`、`hvigor`、`hdc`、`emulator`、日志封装成统一入口，还带项目脚手架、**本地文档检索**和 Agent 技能安装。

```bash
# 需要 Node.js >= 22
npm install -g @deveco/deveco-cli@stable

# Linux 上唯一必做的配置：显式指定 CLT 路径
export DEVECO_CLI_CLT_PATH=$HOME/harmonyos/command-line-tools
```

子命令见 `devecocli --help`：
`build / run / update / device / emulator / auth / skills / log / create / init / serve / docs / ui / check / signature / verify`。

> 日志子命令名是 **`log`**，不是 `hilog` —— `hilog` 是设备侧那个工具的名字。

**最短回路**：

```bash
devecocli create --app-name MyApp --api-level 24 --device-types tablet phone
cd MyApp
devecocli build          # 产出 entry/build/default/outputs/default/ 下的 HAP
devecocli run            # 装到设备并拉起
devecocli log --level E  # 看错误日志
```

> **`build` 到底产出什么**：配好 `signingConfigs` 之前只有 `entry-default-unsigned.hap`（未签名，装不上机）；
> `devecocli signature generate` 写进签名配置后才会多出 `entry-default-signed.hap`。
> 所以"构建成功"不等于"能装机"。

**版本与 tag**：npm 上 `@deveco/deveco-cli` 的 dist-tags 是 `stable = 1.3.0-stable`、`latest = 1.3.5`。
官方推荐装 `@stable`，`@latest` 是尝鲜版。**鸿蒙电脑是例外** —— 官方 FAQ 明说鸿蒙电脑版只发布了尝鲜版，
那种环境要用不带 tag 的 `npm install -g @deveco/deveco-cli`。Linux 上两者都能跑（本机实测 `@latest` = 1.3.5 可用）。

### ⚠️ 官方文档把环境变量名写错了

官方《快速入门》写的是 `DEVECO_CLI_CLI_PATH`，**实测这个名字不生效**。本机在 v1.3.5 上做过 A/B：

```bash
# 只设官方文档写的那个名字 → 仍然报错
$ env -u DEVECO_CLI_CLT_PATH DEVECO_CLI_CLI_PATH=~/harmonyos/command-line-tools devecocli device list
Error: DevEco Studio is not available on Linux. Set DEVECO_CLI_CLT_PATH to a Command Line Tools installation.

# 只设 DEVECO_CLI_CLT_PATH → 不再报这个错
$ env -u DEVECO_CLI_CLI_PATH DEVECO_CLI_CLT_PATH=~/harmonyos/command-line-tools devecocli device list
（正常继续执行）
```

工具自己的报错信息里写的也是 `DEVECO_CLI_CLT_PATH` —— **以它为准**。不设这个变量，任何子命令都会报：

```
Error: DevEco Studio is not available on Linux. Set DEVECO_CLI_CLT_PATH to a Command Line Tools installation.
```

> 注意：`devecocli --version` 不设这个变量也照常输出；是**子命令**才报错。

## 三、编辑器：VS Code 路线

Linux 上没有 DevEco Studio 的 GUI，编辑器用 VS Code / VSCodium / Cursor 都行，加 ArkTS 语言插件：

| 插件 | 发布者 | 说明 |
| --- | --- | --- |
| HarmonyOS-ArkTS | `huawei-developer` | LSP 级补全/跳转/诊断、json5 校验。**注意**：文档要求配置 DevEco Studio 安装目录（`arkts.deveco.path`），**Linux 上能否指向 CLT 未实测** |
| HarmonyOS Dev Assistant | HuaweiDeveloperServicePlatform | AI 编码助手 + ArkTS LSP |
| HarmonyOS Dev Tools | 社区 | 明确支持 `harmony.commandLineToolsSearchPaths`、`harmony.hdcPath`、`harmony.hvigorPath`，对纯 CLT 环境更友好 |
| ArkTS Project Manager / Arkcode | 社区 | 工程创建 + 语言支持，部分支持 codelinter |

如果是纯命令行 + AI Agent 的场景，**`devecocli docs` 比编辑器补全更管用**（见 [入门 / 01](../start/01-学习路径.md)）。

## 四、签名（最容易翻车的一步）

```bash
devecocli auth login
devecocli signature generate --product default
```

它会生成 p12/csr、去云端换证书、下载 p7b，并把这些写进 `build-profile.json5`。

### 五个坑（按危险程度排）

**0. CLI 的 `signature generate` 有个鸡生蛋的设备预检 —— 这条是 CLI 独有的，不能拿 DevEco Studio 的经验套。**

它签之前会查「AGC 云上本团队是否已有设备」；没有就回退查本地 `hdc`，
**但本地 USB 真机不算数**（只认模拟器 serial `127.0.0.1:*`）→ 直接抛 `DEVICE_MISSING` 硬停。
而它内部本来有个「把本地设备自动加进 AGC」的步骤，却跑在预检**之后**，被提前掐断。

表现很有迷惑性：`devecocli device list` / `device view` 都能正常看到平板，**所以这不是设备识别问题**。

> **解法**：先去 AGC 网页把平板 UDID 加为调试设备（一次即可，之后云上非空就放行了）。
> 拿 UDID：`hdc shell bm get -u`。

**1. 联网子命令会被 `http_proxy` / `https_proxy` 静默搞坏，而且不报错。**

`devecocli` 走代理时连不上后端，**失败方式是「假装成功」**：`devecocli auth status` 会打印 `Not logged in`
并 **`EXIT=0`**，看起来像"没登录"，实际是代理拦住了。本机实测（v1.3.5）：

```bash
$ devecocli auth status                                  # 带 http_proxy
Not logged in
EXIT=0

$ env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY devecocli auth status
Current user: <用户名>
EXIT=0
```

**所以 `auth status` 不能用来判断登录状态**（除非先去掉代理）。凡是要联网的子命令
（`auth` / `signature` / `update` / `emulator image` / `create` 等）都建议套一层去代理。
`docs search` / `docs read` 是本地离线文档，不受影响。

>`scripts/dev.sh` 已经默认帮你剥掉代理；确实需要代理时设 `HDOS_KEEP_PROXY=1`。

**2. `build-profile.json5` 不能整个提交，也不能整个忽略。**

它同时含两样东西：

- 构建必需的 `products` / `modules` 配置 —— **必须**进 Git，否则全新 clone 无法构建；
- 签名后写进去的加密密码 —— **不能**进 Git。

正确做法是**保持文件被跟踪**，用 `git update-index --skip-worktree build-profile.json5` 把本机的签名改动隔离在本地。
**把它写进 `.gitignore` 是个常见错误。**

**3. 自动签名拿不到按"应用身份"授权的服务**（如 Map Kit 花瓣地图）。

表现是构建、安装、启动都正常，**地图瓦片一片空白且不报错**。

正确做法：保留自动签名生成的密钥对，去 AGC 为真实应用建一个 debug Profile
（包名、APP ID、证书、调试设备 UDID 都要对），下载 p7b 后把 `build-profile.json5` 的 `profile:` 指过去。

验证：`hdc shell` 执行 `bm dump -n <包名>`，看 `appIdentifier` 是否与 AGC 一致。

**4. 签名身份决定应用数据。**

换签名安装会被视为全新安装，`/data/app/el2/100/base/<包名>` 的 uid 变了，应用设置全丢。
所以：跨机器（Windows 上 DevEco 签一套、Linux 上 CLI 签另一套）交替安装 = 数据反复被清；
想让多平台共用，就把 p12 + p7b 同步过去。

### 另外两个容易踩的

- **系统时间要对到秒。** 签名失败报
  `The signature does not take effect or has expired. The current system time may be inaccurate. Please calibrate the system time and sign again.`
  时，原因是**本机时间与服务器时间不一致**，不是证书坏了。官方要求与北京时间比对，精确到 1–2 秒。
- **别用 `devecocli run --uninstall`**：会把应用 `preferences/` 整个删掉 —— 等于换签名安装的效果，数据全丢。

## 五、模拟器

CLT 26.0.0 自带 emulator，Linux 上可用：

```bash
devecocli emulator license accept                                    # 非交互环境先接受协议（先看 license view）
devecocli emulator image list --all
devecocli emulator image download --device-type tablet --os-version "HarmonyOS 6.1.1(24)"
devecocli emulator create mytab --device-type tablet --os-version "HarmonyOS 6.1.1(24)"
devecocli emulator start mytab --no-window
```

实测坑：

- **无图形环境必须加 `--no-window`**，不加会报 `The x11 environment is incompleted`。
  `--help` 原文：`--no-window … required on Linux hosts without a GUI`。**不需要起 Xvfb。**
- **镜像 API 版本必须 ≥ 应用的 `compatibleSdkVersion`**，否则装不上。
- 非默认屏幕尺寸用 `--screen "宽 高 dpi 英寸"`（720–3500 / 720–3500 / 240–640 / 3.5–9；折叠屏传两组值）。
  CLI 上 `--screen-profile <model>` 也在，但**底层 `Emulator` 二进制的 `-screenProfile` 旧镜像可能不认** —— 两者不是同一个接口，别混。
- 文档里出现的 `-delete` / `-force` / `-screenProfile` 这类**单横线**开关属于**底层 `Emulator` 二进制**，
  不是 `devecocli emulator` 的子命令。`devecocli emulator delete` 只有 `--path`，**没有** `--force`。
- **模拟器上地图渲染的文字会变实心色块**（不是缺字体），要带地图的截图只能用真机。

## 六、CI / Docker

- CI 里用 CLT 就够了，构建、签名、装包都能跑。
- 官方 FAQ 给了 Dockerfile 搭 CLT 流水线的做法：`FAQ/命令行工具/使用Dockerfile搭建Command_Line_Tools流水线/faqs-command-line-tool-27`
  （另有「无网络流水线搭建」一篇，适合离线环境）。
- 社区也有现成镜像（Ubuntu + JDK + CLT），**体积说法未经核实**，用前自己 `docker images` 看一眼。

## 七、能力边界：什么时候仍然需要 Windows / macOS

不是所有事 CLI 都能替代：

- **图形化调试器**（断点、变量监视、性能分析器、UI 设计器）—— CLI 给不了，需要 DevEco Studio。
- **AGC 控制台操作** —— 建证书、建 Profile、配地图等按应用身份授权的服务，必须在网页控制台点。
  签名本身 CLI 能做，**但第一次要先去 AGC 把调试设备加上**（见"签名"坑 0），这一步替代不了。
- **上架提交、隐私政策托管、APP 备案** —— 都是网页流程。
- **图形密集的验证** —— 模拟器不如真机。

反过来说，如果诉求是"在 Linux 上写代码、构建、跑 CI、甚至让 AI Agent 独立完成开发闭环"，CLT 这条路是够的。
