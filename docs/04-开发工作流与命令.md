# 04 开发工作流与命令

**目标形态**：在终端里写 ArkTS → 命令行构建 → 装到平板 → 看日志/看屏幕 → 继续改。**全程不需要图形界面。**

```
        ┌──────────────── Agent（终端）────────────────┐
        │  读文档 → 改 .ets → 跑构建 → 读日志 → 再改      │
        └───────┬──────────────┬───────────────┬────────┘
                │              │               │
         hvigorw/ohpm      hdc(USB/TCP)     devecocli
                │              │               │
           编译产物 hap      平板实机      ui screenshot
                             hilog/aa/bm     hilog/ui layout
```

工具装在哪、什么版本、怎么进 PATH → [02](02-工具链与工具位置.md)。
调试手段（日志、UI 树、截图、模拟器）→ [05](05-调试工作流与命令.md)。
打上架包 → [06](06-打包与签名工作流.md)。

## 一、开工前先确认环境

```bash
bash scripts/dev.sh doctor     # 工具链版本 + 设备状态 + shell 探针
```

没封装脚本时，等价于：

```bash
hvigorw --version && ohpm -v && codelinter -v && hdc list targets
```

## 二、一次性准备

### 1. 平板上打开调试开关

设置 > 系统 > 开发者选项（不同版本可能在「关于本机」里连点软件版本号开启）：

- 打开 **USB 调试**（或 **无线调试**）
- 连接电脑后设备会弹授权框，选 **始终信任**

### 2. 确认 hdc 能看见设备

```bash
hdc list targets
```

| 现象 | 先查什么 |
| --- | --- |
| **空列表** | 优先怀疑 USB 线（充电线不是数据线）、拓展坞/前置面板口、Linux USB 权限。**但本机实测不需要 udev 规则也不需要 `sudo`** —— 见 [07](07-踩过的坑.md) 坑 9 |
| 有设备但未授权 | 设备上关掉再打开调试开关，或 `hdc kill -r` 重启服务端重新触发授权弹窗 |
| 有设备但 `shell` 挂住 | **不是设备问题** —— 见 [07](07-踩过的坑.md) 坑 1 |

无线调试：设备上开启后拿到 `IP:端口`：

```bash
hdc tconn 192.168.1.100:5555            # 连接
hdc tconn 192.168.1.100:5555 -remove    # 断开
```

### 3. 取平板 UDID，登记到 AGC

**这是实机调试最关键的一步。** 调试证书/Profile 带设备 UDID 白名单，不在白名单里的设备装不上调试包。

```bash
hdc shell bm get -u          # 或 bash scripts/dev.sh udid
```

拿到 UDID 后到 AGC 设备管理里添加该设备，并确保调试 Profile 包含它。

> ⚠️ **别拿 DevEco Studio 的经验推 CLI。** Studio 的自动签名会**代你把当前连接的设备注册进 AGC**；
> `devecocli signature generate` **不会** —— 它反而有个设备预检，云上一台设备都没有时直接抛 `DEVICE_MISSING` 硬停
> （见 [06](06-打包与签名工作流.md) 签名坑 0）。
> 所以纯 CLI 路径下，「先去 AGC 手工加一台设备」是**必经步骤**，不是"装不上再回头查"的可选项。
> 这是**跨工具的结论不能平移**的典型案例。

> **serial 与 UDID 是两个不同的编号，别混用** —— 登记 AGC 用的是 **UDID**。见 [07](07-踩过的坑.md) 坑 10。

### 4. 生成签名

```bash
devecocli auth login
devecocli signature generate --product default
```

它会生成 p12/csr、换证书、下载 p7b，并写进 `build-profile.json5`。
**该文件含加密密码，但不能整个提交、也不能整个忽略** —— 见 [07](07-踩过的坑.md) 坑 5。

## 三、日常循环

```bash
# 1. 构建（debug）
hvigorw assembleHap -p buildMode=debug --no-daemon

# 2. 装到平板
hdc install entry/build/default/outputs/default/entry-default-signed.hap

# 3. 拉起应用（平板锁屏时会报 10106102 —— 见 05）
hdc shell aa start -b com.example.myapp -a EntryAbility

# 4. 看日志（缓冲很小，要留证据就先落盘）
hdc hilog

# 5. 改代码，回到 1
```

> `hdc install` 装的是**已签名**的 HAP。配好 `signingConfigs` 之前构建只会产出
> `entry-default-unsigned.hap`，**那个装不上机** —— 「构建成功」不等于「能装机」。

用 DevEco CLI 可以压成两条：

```bash
devecocli build     # 产出 entry/build/default/outputs/default/entry-default-signed.hap
devecocli run       # 自动装包 + 拉起
```

`scripts/dev.sh` 把上面都封了一层（带 hdc 卡死自愈）：

```bash
bash scripts/dev.sh build          # 编译
bash scripts/dev.sh run            # 装到平板并拉起
bash scripts/dev.sh log --level E  # 看错误日志
bash scripts/dev.sh ui             # 导出 UI 节点树
bash scripts/dev.sh shot           # 截图
```

## 四、建一个新工程

```bash
devecocli create --app-name MyApp --api-level 26 --device-types tablet phone
cd MyApp
devecocli build
devecocli run
```

- `--device-types` 按目标形态选（**平板优先就写 `tablet`**）。
- `--api-level` 决定 `compatibleSdkVersion` 的初值，之后可在 `build-profile.json5` 改；
  **它必须 ≤ 目标设备/模拟器镜像的系统 API 版本**，否则装不上（见 [07](07-踩过的坑.md) 坑 6）。
- 建出来的就是标准 Stage 模型工程，结构见 [03](03-工程结构与代码规范.md)。

## 五、增量迭代（别每次全量）

```bash
devecocli run --skip-build                                  # 只重装已有产物
devecocli run --apply changes.txt                           # 增量编译成 hqf
devecocli run --module entry --hotreload                    # 常驻 watch，后台跑
devecocli run --module entry --hotreload-apply changes.txt  # 热重载，不重启应用

devecocli run --hotreload stop     # 用完必须停！（或 bash scripts/dev.sh hotreload-stop）
```

> ⚠️ `--hotreload` 是**常驻进程**，用完**必须显式停掉**，否则 hvigor 的 watch 会话一直挂着，
> 之后每次构建都在等它。**别用 `kill` 猜进程名** —— CLI 自己提供了 stop 动作。见 [07](07-踩过的坑.md) 坑 8。
>
> 热重载只覆盖**非状态类**改动（UI 属性、文本、方法体）；`@State` 之类的改动要走全量。

### 全量重建的参考耗时

本机在迁移后的工程内两次独立实测：**34 任务 / 约 2.5 秒**（2.49s / 2.53s）。
换机器对比时**以任务数为准**，时间会因机器而异。

## 六、写代码时的检查

```bash
devecocli check arkts      # ArkTS 静态检查
devecocli check lint       # Code Linter
devecocli check compat --source-version X --target-version Y   # 破坏性变更扫描
```

> ⚠️ `devecocli check lint` 会打印一句 `Files checked: 0`，**这个数字不反映实际检查范围**。
> 结果要当真时，用裸 `codelinter -c code-linter.json5` 交叉验证。

**写完代码的自查清单在 [03](03-工程结构与代码规范.md) 第七部分。**

## 七、让 Agent 更高效

```bash
devecocli skills list                    # 技能市场
devecocli skills find 崩溃               # 按关键词找
devecocli init --agent opencode          # 给指定 Agent 装技能
devecocli init --mcp --agent opencode --project ./MyApp   # 配 ArkTS/C++ 语法检查的 MCP

devecocli docs search 地图 定位           # 本地文档检索
devecocli docs read <完整路径>            # 读全文（必须传完整路径）
```

`devecocli docs` 的用法单独一篇：[01](01-查证优先.md)。

## 八、命令速查

```bash
# 设备
hdc list targets
hdc tconn <ip:port>                       # 无线连接
hdc shell bm get -u                       # 取 UDID
hdc shell bm dump -n <bundle>             # 应用信息
hdc install <xxx.hap>                     # 安装
hdc uninstall <bundle>                    # 卸载
hdc shell aa start -b <bundle> -a <ability>
hdc shell aa force-stop <bundle>
hdc hilog                                 # 日志
hdc kill -r                               # 会话卡死时重启服务端（见 07）
hdc fport tcp:8080 tcp:8080               # 端口转发
hdc file send <src> <dst>

# 构建
hvigorw assembleHap -p buildMode=debug --no-daemon
hvigorw assembleApp --no-daemon           # 上架用 .app
hvigorw clean --no-daemon
ohpm install

# DevEco CLI
devecocli build | run | log | device list
devecocli ui layout | screenshot | click | swipe | text
devecocli check lint | arkts | compat

# 本仓库封装
bash scripts/dev.sh doctor | build | run | log | ui | shot | udid
bash scripts/dev.sh keepawake | keepawake-restore | recover | hotreload-stop
```

> `hvigorw` 大部分命令要在**工程根目录**下执行；`-v` / `--version` / `-h` 这类可任意路径执行。
> **CI / 脚本里一律加 `--no-daemon`**，避免 daemon 状态影响结果（见 [07](07-踩过的坑.md) 坑 11）。
