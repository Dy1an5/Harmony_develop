# 01 查证优先：官方文档入口与离线检索

**这是所有开发动作的前置。** 在写任何 ArkTS 代码之前先读这一篇 —— 不读它，后面几篇都会把你带偏。

---

## 为什么不能凭记忆写鸿蒙 API

模型的「鸿蒙知识」大多是从 **TypeScript** 和 **Android** 经验外推出来的，而 ArkTS 的现实是：

- **API 面窄**：很多 TS / Android 里理所当然的写法在 ArkTS 里**不存在**（见 [03](03-工程结构与代码规范.md) 的语言限制清单）。
- **迭代快**：API 版本之间行为会变，`compatibleSdkVersion` 不同，同一段代码结果可能不同。
- **失败方式隐蔽**：凭记忆编出来的 API **常常能编译过**，运行时才报错或静默失效 —— 比编译不过更难查。

**所以：先 `devecocli docs search`，再写代码。** 这条能把出错率降一个数量级，是 `AGENTS.md` 的红线之一。

---

## 一、最省事的查法：`devecocli docs`

装好 DevEco CLI 之后，**官方文档已经躺在本地**（实测 **15062 篇**），**不需要联网**：

```bash
devecocli docs search <关键词>      # 检索，打印 documentId + 摘要
devecocli docs read <完整路径>      # 读全文
devecocli docs catalog              # 列目录
devecocli docs update               # 更新语料（这个要联网）
```

### 三个必须知道的细节

**1. `docs read` 必须传 `docs search` 打印的完整路径。**

只给末尾的短 slug 会返回 `Document not found`。例如：

```bash
# ✗ 不行
devecocli docs read arkts-state

# ✓ 要完整路径
devecocli docs read "开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/学习UI范式状态管理/状态管理_V1/管理组件拥有的状态/State装饰器_组件内状态/arkts-state"
```

**2. 语料装在 SQLite 索引里，只能按关键词搜，不能按目录列。**

索引在 `~/.local/share/deveco-cli/docs/.index/search.db`（约 45M）。
想「看一下某个目录下有什么」，**把目录前缀当关键词搜**，比翻 `catalog` 快：

```bash
devecocli docs search "学习UI范式状态管理"
```

**3. 别把 `docs update` 和 `devecocli update` 写反。**

前者更新**文档语料**（联网），后者升级 **CLI 本体**。

## 三、查不到时的降级路径

`devecocli docs` 的语料不是全量的，按顺序试：

| 情况 | 怎么办 |
| --- | --- |
| 关键词搜不到 | 换**目录前缀**搜（见上），或换同义词（「状态管理」→「UI范式状态管理」） |
| 语料版本落后 | `devecocli docs update`（联网），或直接查官方在线文档 |
| 官方文档也说不清 | 读 **SDK 里的类型声明**：`$DEVECO_SDK_HOME/default/openharmony/ets/api/*.d.ts` —— 这是最权威的，签名和参数不会错 |
| 怀疑是版本差异 | 先确认工程的 `compatibleSdkVersion`（见 [03](03-工程结构与代码规范.md)），再对文档版本 |
| 报错看不懂 | 拿错误码去 `devecocli docs search <错误码>`，官方 FAQ 按码可检索 |
