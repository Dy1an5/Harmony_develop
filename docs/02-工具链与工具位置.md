# 02 工具链与工具位置

**静态清单**：这台机器上有哪些工具、装在哪、什么版本、怎么进 PATH。
流程性内容不在这里 —— 开发见 [04](04-开发工作流与命令.md)，调试见 [05](05-调试工作流与命令.md)，打包见 [06](06-打包与签名工作流.md)。

---

## 一、前提：Linux 上没有 DevEco Studio

官方只提供 **Windows / macOS / 鸿蒙电脑** 三个平台的 DevEco Studio，**没有 Linux 版**。
但官方把整套工具链拆出了一个 **Command Line Tools（CLT）** 包，**有 Linux 版**，官方还专门写了 `macOS/Linux` 的配置章节。

| 平台 | DevEco Studio | Command Line Tools | 最低版本 |
| --- | --- | --- | --- |
| Windows | 支持 | 可选 | Studio 6.0.0 / CLT 26.0.0 |
| macOS | 支持 | 可选 | 同上 |
| 鸿蒙电脑（HarmonyOS PC） | 支持（要求 HarmonyOS 7.0+） | 可选 | 同上 |
| **Linux** | **不支持** | **必选** | CLT 26.0.0 |

> 结论：**Linux 上不是"不能开发鸿蒙"，而是"必须显式告诉工具链工具在哪"**（因为没有 Studio，只有 CLT）。

## 二、通用要求（换机器也要满足）

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| 系统 | Linux x86_64，**GLIBC ≥ 2.28** | 官方 CLT 要求 |
| Command Line Tools | **≥ 26.0.0** | 自带 SDK，无需另下 |
| JDK | **21** | 官方原文：CLT ≥ 26.0.0 推荐 JDK 21；26.0.0 以下推荐 17 |
| Node.js | **≥ 22** | hvigor / ohpm 运行时。建议直接用 CLT 自带的 `tool/node` |

**系统资源**（官方建议）：内存 16 GB 及以上（最小 8 GB），硬盘 100 GB 及以上。

## 三、CLT 里有什么

> 官方描述：CLT 集合了 HarmonyOS 应用开发所用的系列工具，包括代码检查 `codelinter`、堆栈解析 `hstack`、
> 命令行构建 `hvigorw`、三方依赖管理 `ohpm`，以及 SDK 中包含的一系列工具（含设备调试工具 `hdc`）。
> **HarmonyOS SDK 已嵌入命令行工具中，无需额外下载配置。**

| 工具 | 作用 |
| --- | --- |
| `hvigorw` | 构建（类比 Gradle） |
| `ohpm` | 三方依赖管理（类比 npm） |
| `hdc` | 设备调试（类比 adb） |
| `codelinter` | 代码检查（Code Linter） |
| `hstack` | 崩溃栈解析 |
| `emulator` | 模拟器 |
| `hap-sign-tool.jar` | 签名工具（在 `sdk/default/openharmony/toolchains/lib/` 下） |

**外加**：

| 工具 | 作用 | 备注 |
| --- | --- | --- |
| ArkTS / ArkUI / ArkCompiler | 语言、UI 框架、编译器 | 编译成**方舟字节码**，不是 JS |
| AppGallery Connect (AGC) | 应用全生命周期管理 | **网页控制台**，建应用/传包/提审都在这里 |
| DevEco CLI (`devecocli`) | 把 CLT 封装成统一入口 | npm 包 `@deveco/deveco-cli`，还带本地文档检索 |
| DevEco Testing | 上架前的性能/兼容性/稳定性测试 | 配合云测试、云调试 |

## 四、本机实测值（**换机器后这一节会失效，当参考、别当依据**）

> 以下来自 [Arch Linux + CLT 26.0.0.851 + devecocli 1.3.5 + Huawei MatePad Mini] 的实测。

### 安装位置（**工具分布在三处，不在同一目录 —— 刻意如此，不是遗漏**）

| 工具 | 位置 |
| --- | --- |
| Command Line Tools | `~/harmonyos/command-line-tools/`（7.1G） |
| `devecocli` | `~/.nvm/versions/node/v22.23.2/lib/node_modules/@deveco/` |
| JDK | `/usr/lib/jvm/java-21-openjdk`（系统包） |

> ⚠️ **`devecocli` 跟着 node 版本走** —— 它装在 nvm 的 v22.23.2 前缀里，
> **切换 node 版本后它会消失**，需重装。CLT 那 7.1G 不受影响。

### 版本

| 项 | 值 |
| --- | --- |
| 系统 | Arch Linux x86_64 |
| CLT 来源 | `commandline-tools-linux-x64-26.0.0.851.zip` |
| SDK | CLT 自带 **HarmonyOS SDK 26.0.0 Release**（Ohos_sdk_public 26.0.0.105，**API 26**） |
| JDK | 21.0.12.1 |
| Node.js | v22.23.2（npm 10.9.8，pnpm 12.4.1） |
| `devecocli` | 1.3.5 |
| 目标设备 | Huawei MatePad Mini（MLR-AL00），HarmonyOS **API 26** |

工具链版本（`--version` 实得）：

| 工具 | 版本 |
| --- | --- |
| hvigor | 6.26.8 |
| ohpm | 26.0.0.630 |
| codelinter | 6.0.240 |
| hstack | 6.1.0 |
| hdc（CLT 自带） | 3.2.0f |

### 环境变量

CLT 通过 PATH 暴露工具；`hdc` 在 SDK 的 toolchains 目录下，要单独加：

```bash
export DEVECO_SDK_HOME=$HOME/harmonyos/command-line-tools/sdk
export HDC_HOME=$DEVECO_SDK_HOME/default/openharmony/toolchains
export PATH=$HOME/harmonyos/command-line-tools/bin:$HDC_HOME:$PATH

# devecocli 唯一必做的配置：显式指定 CLT 路径
export DEVECO_CLI_CLT_PATH=$HOME/harmonyos/command-line-tools
```

> 本仓库把这些封装在 `scripts/env.sh`（**幂等**，`~/.zshrc` 已 source）。常用命令封装在 `scripts/dev.sh`。
>
> `scripts/dev.sh` 还会自动 source 仓库根的 **`.env.local`**（gitignored），并把
> `HDOS_DEVICE_SERIAL` / `HDOS_BUNDLE_NAME` 映射成 `HDOS_TARGET` / `BUNDLE_NAME`。
> 换机器时把这些值写进自己的 `.env.local` 就行，**不用改脚本**；没有这个文件也能正常工作。
>
> ⚠️ **`default/openharmony/` 这个目录名不是你选了 OpenHarmony** —— SDK 就装在 CLT 的这个固定路径下，
> `HDC_HOME` 和 `hap-sign-tool.jar` 都在里面，路径写死了，改不掉也不用改。

## 五、两个已知的坑

### 1. 官方文档把环境变量名写错了

官方《快速入门》写的是 `DEVECO_CLI_CLI_PATH`，**实测这个名字不生效**。本机在 v1.3.5 上做过 A/B：

```bash
# 只设官方文档写的那个名字 → 仍然报错
$ env -u DEVECO_CLI_CLT_PATH DEVECO_CLI_CLI_PATH=~/harmonyos/command-line-tools devecocli device list
Error: DevEco Studio is not available on Linux. Set DEVECO_CLI_CLT_PATH to a Command Line Tools installation.

# 只设 DEVECO_CLI_CLT_PATH → 不再报这个错
$ env -u DEVECO_CLI_CLI_PATH DEVECO_CLI_CLT_PATH=~/harmonyos/command-line-tools devecocli device list
（正常继续执行）
```

**以工具自己报错信息里写的 `DEVECO_CLI_CLT_PATH` 为准。** 不设这个变量，任何子命令都会报上面那个错。

> 注意：`devecocli --version` 不设也照常输出；**是子命令才报错**。

### 2. `devecocli` 的版本标签

npm 上 `@deveco/deveco-cli` 的 dist-tags 是 `stable = 1.3.0-stable`、`latest = 1.3.5`。
官方推荐装 `@stable`，`@latest` 是尝鲜版。

**鸿蒙电脑是例外** —— 官方 FAQ 明说鸿蒙电脑版只发布了尝鲜版，那种环境要用不带 tag 的
`npm install -g @deveco/deveco-cli`。Linux 上两者都能跑（本机实测 `@latest` = 1.3.5 可用）。

## 六、CLT 的安装步骤（Linux）

1. 到下载中心取 Command Line Tools：https://developer.huawei.com/consumer/cn/download/command-line-tools-for-hmos
   选 **Linux** 版，按页面「工具完整性」指引做校验。
2. 解压到任意目录，例如 `~/harmonyos/command-line-tools`。
3. 按上面「环境变量」一节配 PATH。
4. 验证：

```bash
codelinter -v
hdc list targets
devecocli device list        # 需要 DEVECO_CLI_CLT_PATH
```
