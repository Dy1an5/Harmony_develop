## 二、四个配置文件管什么

**这是最容易搞混的地方。**

### `AppScope/app.json5` —— 应用的身份证

应用级全局配置，**每个工程必须有且只有一个**：

```json5
{
  "app": {
    "bundleName": "com.example.myapp",   // 包名，与备案/软著强绑定，定了别改
    "vendor": "example",
    "versionCode": 1000000,               // 整数，上架递增
    "versionName": "1.0.0",
    "icon": "$media:app_icon",
    "label": "$string:app_name"
  }
}
```

> ⚠️ **`bundleName` 定了就不要改** —— 它和 APP 备案、软著登记名称强绑定，改名要联动变更（见 [08](08-发行与合规.md)）。

### 模块级 `src/main/module.json5` —— 这个 HAP 里有什么

| 字段 | 管什么 |
| --- | --- |
| `name` / `type` | 模块名、类型（`entry` / `feature` / `har` / `shared`） |
| `deviceTypes` | 支持哪些设备形态：`phone` / `tablet` / `tv` / `wearable` / `2in1` … |
| `mainElement` | 主入口 Ability 名 |
| `pages` | 指向 `$profile:main_pages`，那里列了所有页面路径 |
| `abilities` | **UIAbility 注册**：`name`、`srcEntry`（.ets 路径）、`icon`、`label`、`startWindow*`、`exported`、`skills` |
| `extensionAbilities` | 扩展能力注册（卡片、输入法等） |
| `requestPermissions` | **权限声明**：`name`（`ohos.permission.*`）、`reason`、`usedScene` |

`abilities` 里 `skills` 带 `entity.system.home` + `ohos.want.action.home` 的那个，就是桌面图标点开的入口。

> ⚠️ `module.json5` 里的 `pages` 指向 `resources/base/profile/main_pages.json`，
> **新建的页面必须在那里面登记**，否则路由找不到。

### 工程级 `build-profile.json5` —— 构建、签名、SDK 版本

```json5
{
  "app": {
    "signingConfigs": [                  // 签名方案（见 06）
      { "name": "default", "type": "HarmonyOS", "material": { /* p12 / p7b / 密码 */ } }
    ],
    "products": [                        // 产品品类
      {
        "name": "default",
        "signingConfig": "default",      // 不配就是"不签名"
        "bundleName": "com.example.myapp",
        "compatibleSdkVersion": "26.0.0",// 最低兼容版本，见下方说明
        "targetSdkVersion": "26.0.0",
        "runtimeOS": "HarmonyOS"
      }
    ]
  }
}
```

**三个 SDK 版本字段的区别**（容易搞混）：

| 字段 | 含义 | 什么时候要动 |
| --- | --- | --- |
| `compatibleSdkVersion` | **必选。**能安装的最低系统版本 | 目标设备系统版本低于它 → **装不上** |
| `targetSdkVersion` | 可选。系统在更高版本上是否对新 API 行为做前向兼容 | 建议显式配置 |
| `compileSdkVersion` | 可选。编译用哪个 SDK | HarmonyOS 运行时不需要配，默认用工具链自带的 |

> **从 API 26.0.0 起，HarmonyOS 和 OpenHarmony 的写法统一了**：三个字段都是字符串，写 `"26.0.0"`。
> API 26.0.0 之前：HarmonyOS 是字符串 `"6.1.1(24)"`，OpenHarmony 是数值 `24`。**别把两套写法混着抄。**

> ⚠️ **这个文件不能整个提交，也不能整个忽略。** 它同时含构建必需的 `products`/`modules` 配置（必须进 Git）
> 和签名后写进去的加密密码（不能进 Git）。做法见 [07](07-踩过的坑.md) 的坑「build-profile.json5 既不能提交也不能忽略」。

### `oh-package.json5` —— 依赖

相当于 `package.json`：

```json5
{
  "name": "myapp",
  "version": "1.0.0",
  "dependencies": {},
  "devDependencies": {}
}
```

装依赖用 `ohpm install`，产物落在 `oh_modules/`（相当于 `node_modules`），**不要提交**。

## 三、资源怎么组织

`resources/` 下分四类目录：

| 目录 | 放什么 | 怎么访问 |
| --- | --- | --- |
| `base/element/` | 字符串、颜色、浮点、整数、布尔、数组 —— **每类一个 json 文件**（只放文件、不放子目录） | `$r('app.string.xxx')` |
| `base/media/` | 图片、音频、视频（png / jpg / gif / svg / webp / bmp / mp3 / mp4） | `$r('app.media.xxx')` |
| `base/profile/` | 自定义 json 配置（如 `main_pages.json`） | `$profile:xxx` |
| `rawfile/` | 任意格式原始文件，**不编译、不分配资源 ID** | 按文件路径读 |
| `resfile/` | 同上，但安装后会被解压到应用沙箱，**只读** | 通过 `resourceDir` 拿路径 |

访问语法：

```typescript
Text($r('app.string.string_hello'))
  .fontColor($r('app.color.color_emphasize'))
  .fontSize($r('app.float.text_size_headline1'))

Image($r('app.media.app_icon'))

// 带占位符：string.json 里写 %1$s / %2$d 时
$r('app.string.label', 'aaa', 444)
```

**同名资源的优先级**（高 → 低）：`AppScope/resources` > 当前 HAP 模块 > 依赖的 HAR。

> **限定词目录**（按语言/横竖屏/设备类型/深色模式自动匹配，如 `zh_CN-car-ldpi`）不在本文展开；
> 需要多设备/多语言适配时查 `开发指南/资源分类与访问/resource-categories-and-access`。

# 第二部分：ArkTS 不是 TypeScript

**这是最容易吃亏的地方：TS 能编过的代码，ArkTS 可能直接编译不过。**

ArkTS 保留 TS 的大部分语法，但为了编译成**方舟字节码**做优化，砍掉了所有"运行时才知道类型"的动态特性。

## 一、必须记住的四条

| 规则 | 说明 |
| --- | --- |
| **强制静态类型** | 不许 `any` / `unknown`，不许靠类型推断蒙混；函数返回类型建议显式标注 |
| **禁止运行时改对象结构** | 不能给对象动态加属性、不能 `delete`、不能改方法 |
| **严格空安全** | `null` / `undefined` 不能传给 `string` 这类非空类型，编译期就拦；可能为空要标 `string \| undefined`，取值用 `?.` |
| **类的属性必须显式初始化** | 声明时或构造函数里赋初值，不能像宽松 TS 那样留着 undefined |

```typescript
// ✗ TS 宽松模式能过，ArkTS 编译失败
class Person {
  name: string;               // 没初始化
  getName(): string { return this.name; }
}

// ✓ ArkTS 写法
class Person {
  name: string = '';          // 显式初始化
  getName(): string { return this.name; }
}

// ✓ 如果确实可能为空，类型要写清楚
class Person2 {
  name?: string;
  getName(): string | undefined { return this.name; }
}
let len = new Person2().getName()?.length;   // 用 ?. 安全访问
```

## 二、常被 TS/JS 习惯坑到的具体条目

- **不支持解构**：`const { a, b } = obj`、参数解构、数组解构都不行，用临时变量代替。
- **不支持 `var`**：用 `let` / `const`。
- **不支持 `for...in`**：用 `for...of` 或普通 `for`。
- **不支持 `Function.apply` / `call` / `bind`**。
- **不支持 `Symbol()`、`globalThis`、`with`**。
- **不支持 index signature**：`obj['field']` 这种按下标访问字段会报
  `Indexed access is not supported for fields (arkts-no-props-by-index)`。
- **不支持 structural typing**：形状一样的两个类型不能互相赋值，要么同一个类，要么显式 `as`。
- **类型转换只能用 `as T`**，不能用 `<T>value`；而且 `as` 只在编译期生效，运行时不做转换。
- **对象字面量必须有明确的类型标注**，不能凭空构造。
- **不支持声明合并**（同名 interface / enum 合并 → `Cannot redeclare block-scoped variable`）。
- **一个文件里的函数内不能再声明函数**（不支持函数声明的嵌套）。
- **不支持 `catch` 里标注类型**：写 `catch (e)`，然后自己判类型。
- **`.ets` 可以 import `.ts` / `.js`，反过来不行**。

**完整清单**（按字母序列了七十多条）：
`开发指南/学习ArkTS语言/从TypeScript到ArkTS的适配指导/从TypeScript到ArkTS的适配规则/typescript-to-arkts-migration-guide`

> **有 Java/Kotlin 背景的话建议先看这一篇**，比啃 TS 文档快：
> `开发指南/学习ArkTS语言/面向其他语言的ArkTS迁移指导/从Java到ArkTS的迁移指导/getting-started-with-arkts-for-java-programmers`

**为什么这么严**：不是为了折腾人 —— ArkTS 编译成方舟字节码（不是 JS），静态类型信息让引擎不用在运行时反复做类型检查，
性能和稳定性都更好。详见 `开发指南/学习ArkTS语言/从TypeScript到ArkTS的适配指导/ArkTS语法适配背景/arkts-migration-background`。

> 从 **API 10** 起 `.ets` 文件走「标准模式」，**任何 ArkTS 语法违规都会让编译失败**；
> `compatibleSdkVersion < 10` 才是「兼容模式」（只告警）。现在的工程基本都是标准模式。

# 第三部分：ArkUI 声明式 UI

> **思维转变**：Android 是「创建 View → 拿到引用 → 改属性」；ArkUI 是「**用代码描述某个状态下 UI 长什么样**」，
> 状态一变，框架自己重算受影响的部分。**不要找"控件对象"**。

## 一、组件与页面

```typescript
@Entry            // 页面入口，一个页面只能有一个
@Component        // 自定义组件
struct Index {
  build() {       // build() 里描述 UI，只能有一个根组件
    Column() {
      Text('Hello')
        .fontSize(24)
        .fontWeight(FontWeight.Bold)
      Button('点我')
        .onClick(() => { /* ... */ })
    }
    .width('100%')
    .padding(16)
  }
}
```

- `@Entry` 装饰的组件是页面根组件；`@Component` 装饰的可复用组件叫自定义组件。
- **`build()` 里只能有一个根组件**。
- 组件的**属性、事件、子组件**都写在链式调用/嵌套里。
- 自定义组件用 `export struct` 导出，在别处 `import` 后直接用。

`@Entry` 的细节与 `EntryOptions`（`routeName` 等）：
`API参考/ArkUI_方舟UI框架/ArkTS组件/自定义组件/自定义组件装饰器/Entry_页面入口/ts-universal-entry`

## 三、渲染控制

| 语法 | 用途 |
| --- | --- |
| `if` / `else` | 条件渲染 |
| `ForEach` | 循环渲染 |
| `LazyForEach` | 大数据量懒加载（长列表必用） |
| `Repeat` | 可复用的循环渲染（较新） |

```typescript
ForEach(this.items, (item: Item) => {
  ListItem() { Text(item.title) }
}, (item: Item) => item.id)     // 第三个参数是 key 生成函数，不要省
```

# 第四部分：状态管理（重点）

**这是从命令式 UI 转过来最需要花时间的一块。** 记住一句话：**变量加了装饰器，改动才会驱动 UI 更新。**

## 一、V1 装饰器（主流）

| 装饰器 | 作用域 | 数据流向 |
| --- | --- | --- |
| `@State` | 组件内 | 组件自己的状态，**必须本地初始化**；父组件传入只能当初始值，后续不同步 |
| `@Prop` | 父子 | **单向**：父 → 子；子改只在子内部生效 |
| `@Link` | 父子 | **双向**：父子互相同步 |
| `@Provide` / `@Consume` | 跨层级 | 祖先 ↔ 后代，不用逐层传参 |
| `@Observed` / `@ObjectLink` | 嵌套对象 | 类对象属性变化能触发刷新 |
| `@Watch` | 任意 | 状态变化时回调 |
| `AppStorage` / `LocalStorage` | 全局 / 页面级 | 应用级、页面级状态存储 |

```typescript
@Entry
@Component
struct Counter {
  @State count: number = 0            // 组件内状态

  build() {
    Column() {
      Text(`count = ${this.count}`)
      Button('+1').onClick(() => { this.count++ })   // 改状态 → UI 自动更新
      Child({ value: this.count })    // 传给子组件
    }
  }
}

@Component
struct Child {
  @Prop value: number                 // 只跟着父组件变
  build() { Text(`child: ${this.value}`) }
}
```

**`@State` 的硬性规则**（另外几个装饰器同理）：

- **必须本地初始化**，不能只靠父组件传。
- 能装饰的类型有限：`object` / `class` / `string` / `number` / `boolean` / `enum` 及其数组；
  API 10 起支持 `Date`，API 11 起支持 `Map` / `Set` / `undefined` / `null` 及联合类型。**Function 类型不允许**。
- 只能从组件内部访问（私有）。

官方详解：`开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/学习UI范式状态管理/状态管理_V1/管理组件拥有的状态/State装饰器_组件内状态/arkts-state`

## 二、V2 装饰器（新工程设计就考虑）

V2 是官方在推的新体系：`@ComponentV2` + `@Local` / `@Param` / `@Event` / `@Provider` / `@Consumer`，
数据对象用 `@ObservedV2` + `@Trace`，全局状态用 `AppStorageV2` / `PersistenceV2`。

V2 观测能力更强、能深度观测类属性，但 **V1 和 V2 不能随便混用**（有专门的混用规则和版本条件）。

- 选型与区别：`FAQ/UI框架/UI界面/状态管理V1和V2适用场景介绍/faqs-arkui-885`
- 迁移：`开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/学习UI范式状态管理/状态管理V1-V2迁移指导/V1-V2迁移概述/arkts-v1-v2-migration`

> **实务建议：跟着官方模板和现有工程走。** 新工程用 V1 也能做完，
> 别在不懂两套机制差异的时候自己混搭，容易出「改了状态但 UI 不刷新」这类查不出来的问题。

## 三、状态不刷新的常见原因

1. 变量**没加装饰器** —— 普通成员变量改了不触发渲染。
2. 改了**嵌套对象的属性**，但对象只加了 `@State` 没加 `@Observed` / `@ObjectLink`。
3. `ForEach` 的 key 函数写成了固定值或索引，导致框架认为元素没变。
4. 在装饰器不支持的类型上做文章（比如 `Function`）。

# 第五部分：页面路由

**两套机制并存，选新的那套。**

| 方案 | 状态 | 说明 |
| --- | --- | --- |
| `Navigation` + `NavDestination` | **推荐** | 组件级路由，支持分栏（平板/折叠屏很关键）、转场动画、跨包路由 |
| `router`（`@ohos.router`） | 不推荐 | 老方案，只能单栏，官方有「Router 切换 Navigation」迁移指导 |

```typescript
Navigation() {
  // 首页内容
}
.title('首页')
.mode(NavigationMode.Auto)     // 大屏自动分栏
```

跳转用 `NavPathStack` 的 `pushPath` / `pushPathByName`，返回用 `pop`。
**目标页面要通过 `NavDestination` 承载**，并按官方要求注册路由表。

- 分栏（平板）：`.../组件导航_Navigation_推荐/Navigation分栏开发/arkts-navigation-split-mode`
- 从 router 迁过来：`.../Router切换Navigation/arkts-router-to-navigation`

> **目标是平板的话，优先用 `Navigation` 并打开分栏模式** —— 大屏上单栏铺满宽度体验很差，而 `router` 做不了分栏。

# 第七部分：代码约定与自查清单

## 一、硬性约定

- 语言用 **ArkTS**（不是纯 TypeScript）。**不要用 `any`**、不要运行时改对象结构、不要依赖 TS 的宽松类型推断 —— 这些在 ArkTS 编译期直接报错。
- UI 用 **ArkUI 声明式**写法，状态驱动。不要照搬 Android「拿到 View 再 setText」。
- 页面状态用 `@State` / `@Prop` / `@Link` / `@Provide` / `@Consume` / `@Observed`。
- 构建系统是 **hvigor**（不是 Gradle）；依赖声明在 `oh-package.json5`。
- **不要凭记忆写鸿蒙 API** —— 先查本地文档，见 [01](01-查证优先.md)。

## 二、写完代码自查

- [ ] 没有 `any` / `unknown`，可能为空的类型标了 `| undefined`
- [ ] 类属性都有初值
- [ ] 没有解构、没有 `for...in`、没有动态加属性
- [ ] `build()` 只有一个根组件
- [ ] 驱动 UI 的变量**都加了状态装饰器**
- [ ] `ForEach` 带了正确的 key 函数
- [ ] 新建页面已在 `main_pages.json` 里登记
- [ ] UI 之外的行为不靠「拿控件改属性」实现

## 三、交活前必须跑

```bash
devecocli check arkts      # ArkTS 静态检查
devecocli check lint       # Code Linter
```

> ⚠️ `devecocli check lint` 会打印一句 `Files checked: 0`，**这个数字不反映实际检查范围**。
> 结果要当真时，用裸 `codelinter -c code-linter.json5` 交叉验证。
