# 01 学习路径

从零开始（没有安卓经验也看得懂，有安卓经验会更快）的 HarmonyOS 应用开发路线。

## 先记住三件事

1. **语言是 ArkTS，不是 TypeScript。** ArkTS 在 TS 基础上收紧了静态检查（见 [03](03-ArkTS与ArkUI基础.md)），拿 TS 的写法直接过来会在编译期报错。
2. **UI 是 ArkUI 声明式**，状态驱动。不要照搬"拿到控件对象再 setText"那套。
3. **构建体系是 hvigor**，不是 Gradle。依赖声明在 `oh-package.json5`。

## 最省事的离线文档：`devecocli docs`

装好 DevEco CLI 之后，官方文档已经躺在本地了（**15062 篇**，实测），**不需要联网**：

```bash
devecocli docs search 状态管理          # 关键词检索，打印 documentId + 摘要
devecocli docs read <documentId>        # 读全文
devecocli docs catalog                  # 列目录
devecocli docs update                   # 更新语料（这个要联网）
```

两个必须知道的细节：

- **`docs read` 必须传 `docs search` 打印的完整路径**，只给末尾的短 slug 会返回 `Document not found`。
  例如要 `开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/学习UI范式状态管理/状态管理_V1/管理组件拥有的状态/State装饰器_组件内状态/arkts-state`，
  而不是 `arkts-state`。
- 语料是**装进 SQLite 索引**的（`~/.local/share/deveco-cli/docs/.index/search.db`，约 45M），
  所以**搜关键词很稳、按路径前缀列目录不了** —— 想"看一下这个目录下有什么"，直接把前缀当关键词搜。

```bash
# 目录结构也能搜出来，比翻 catalog 快
devecocli docs search "学习UI范式状态管理"
```

> **这是整条工具链里对 Agent 最有价值的部分。** 鸿蒙 API 迭代快，模型凭记忆写 API 很容易编出不存在的方法；
> 先 `docs search` 再写，能把出错率降一个数量级。这条已经写进 [AGENTS.md](../../AGENTS.md) 的红线。

## 工具链速览

| 工具 | 作用 | 备注 |
| --- | --- | --- |
| ArkTS | 应用开发语言，基于 TypeScript 扩展 | 鸿蒙主力语言，静态检查更严格 |
| ArkUI | 声明式 UI 框架 | 组件、动画、状态管理、布局 |
| ArkCompiler | 统一编译平台 | 编译成方舟字节码，不是 JS |
| DevEco Studio | 官方 IDE，集成开发/调试/预览/签名/打包 | 基于 IntelliJ，**无 Linux 版** |
| AppGallery Connect (AGC) | 应用全生命周期管理 | 建应用、配信息、上传包、提审、发布 |
| Command Line Tools (CLT) | 脱离 IDE 的完整工具链 | 含 `codelinter`、`hstack`、`hvigorw`、`ohpm`、`hdc` 及 SDK；**有 Linux 版** |
| DevEco CLI | 把 CLT 封装成单一命令入口 | npm 包 `@deveco/deveco-cli` |
| ArkUI-X | 官方开源跨平台框架 | 一套 ArkTS 代码跑 HarmonyOS / OpenHarmony / Android / iOS |
| DevEco Testing | 上架前的性能/兼容性/稳定性测试 | 配合云测试、云调试 |

Linux 上怎么把上面这些装起来，见 [工具链 / 01 环境搭建](../toolchain/01-环境搭建.md)。

## 建议的阅读顺序

1. **概念**：ArkUI 框架、应用模型（Stage 模型）的基本概念 —— 官方 `开发指南/快速入门/开发准备/start-overview`。
2. **跑通一个 Hello World**：`开发指南/快速入门/构建第一个HarmonyOS应用_ArkTS/start-with-ets-stage`。
   Linux 上用命令行建工程见 [工具链 / 01](../toolchain/01-环境搭建.md)。
3. **工程结构**：先把 [02 工程结构](02-工程结构.md) 读一遍，知道哪个文件管什么。
4. **ArkTS 语言**：先看 [03](03-ArkTS与ArkUI基础.md) 里的"语言限制"一节，再看官方
   `开发指南/学习ArkTS语言/ArkTS语言介绍` 与 `.../从TypeScript到ArkTS的适配规则`。
   **有 Java 背景的可以直接看 `开发指南/学习ArkTS语言/面向其他语言的ArkTS迁移指导/从Java到ArkTS的迁移指导`**，比啃 TS 文档快。
5. **ArkUI 声明式 UI**：重点砸在**状态管理**和**布局**上，这是从命令式 UI 过来最大的思维转变。
6. **应用模型**：UIAbility 生命周期、页面路由、Context —— 对应 Android 的 Activity 与应用模型。
7. **基础能力**：数据存储、网络、权限、通知。
8. **需要复用原生能力**时 → [04 从安卓迁移](04-从安卓迁移.md) 里的平台桥接。
9. **签名与打包上架** → [开发者注册与上架发行](../01-开发者注册与上架发行.md)。

## 版本对齐

- 当前版本参考：**HarmonyOS 7（API 26）**。
- 版本号在文档 URL 里也有体现（`harmonyos-guides-V5`、`HarmonyOS-Guides`）。查资料时**先确认自己工程的 `compatibleSdkVersion`**，
  别照着别的版本抄。
- 工程里 `compatibleSdkVersion` 必须 **≤ 目标设备的系统 API 版本**，否则装不上（见 [工具链 / 03](../toolchain/03-踩过的坑.md)）。
