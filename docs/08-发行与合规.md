# 08 发行与合规

> 🧑 **这一篇基本是「人工流程」，Agent 代替不了。** 注册、实名、AGC 控制台、备案、软著、提审
> —— 全是网页操作，而且涉及实名信息和法律主体。**Agent 能做的是准备材料清单、核对名称一致性、提醒时限。**

**结论先行**：个人开发者可以注册、可以上架，注册与实名认证免费、**无上架费无年费**
（不像 Apple 有 99 美元/年年费）。但有若干能力和类目对个人不开放。

打包签名是技术活，见 [06](06-打包与签名工作流.md)。这一篇讲的是**打包之后**的事。

## 一、时间线（**别等开发完才动手**）

```
开发 ────────────────────────────────────────┐
                                            │
注册 + 实名 ──┐                              │
             │                              │
APP 备案 ─────┼── 5~20 天 ──────────┐        │
             │                      │        │
软著登记 ─────┴── 1~2 个月 ─────────┼────────┼──> 提审 ──> 上架
                                    │        │
发布证书 + Profile ── AGC，当天 ─────┘        │
                                             │
打包 .app ───────────────────────────────────┘
```

> ⚠️ **备案和软著都有天级到月级的等待期，建议在开发阶段就并行启动。**
> 个人主体第一次备案尤其容易卡，不要等开发完成才动手。

## 二、注册与实名认证

```
1. 注册华为账号（手机号或邮箱）
2. 用该账号登录华为开发者联盟
3. 选择「个人开发者」身份，完成实名认证
4. 同意《华为开发者服务协议》等协议
5. 获得开发者资格，可创建应用 / 申请证书
```

官方说明：**只有实名认证过的开发者才允许进行应用上架分发。**

**实名认证方式**：人脸识别验证；或填写中国大陆身份信息 / 银行卡验证。
入口：华为账号 → 个人信息 / 账号安全 → 实名认证 → 去实名。

**需要准备的材料（个人）**：

- 姓名、地址、联系电话、邮箱
- 身份证号、身份证正反面照片、证件有效期
- 手持证件照片
- 开发者信息、华为账号信息、用户名/昵称、第三方账号信息、工作信息
- **个人开发者承诺函**（上架提交资质时需要，官方提供模板）—— 这条容易漏

**注册条件**：

| 条件 | 说明 |
| --- | --- |
| 年龄 / 行为能力 | 需具备完全民事行为能力，实操口径为年满 18 周岁 |
| 实名 | 必须使用真实身份信息，平台依《网络安全法》等做网络实名制 |
| 主体地区 | 中国大陆主体用大陆身份证；**港澳台及海外个人主体一般不能注册中国大陆开发者联盟账号**（这条来自第三方整理，未在官方文档直接确认），需走华为海外站点 |
| 账号归属 | 一个华为账号对应一个开发者身份；企业和个人不要混用同一账号 |

**费用**：

- 注册华为账号、开发者联盟实名认证：**无收费项**
- 上架分发：**无上架费、无年费**
- 真正会产生费用的地方：
  - 应用内支付 / 广告的收入分成
  - 云服务、云测试、云调试等增值服务
  - 软著加急、电子版权认证等第三方服务（不是华为收的）

**常见坑**：

1. **一开始就用个人手机号注册了企业开发者账号**，导致账号信息和企业信息绑定，后续无法拆分。
   官方建议企业开发者一开始就用企业公共邮箱/手机号注册。
2. **身份证照片不规范**：需原件拍照或彩色扫描，不可隔屏拍摄，边角完整、内容清晰、无反光，
   水印只能一行且不遮挡重要信息。
3. **误以为注册了就能上架**：实名认证只是第一步，APP 备案、资质、签名证书都还要各自走流程。

## 三、名称一致性（**高频驳回原因**）

以下三个名称**必须一致**，修改任何一方都要联动变更：

```
应用在商店的名称  ==  软著登记名称  ==  APP 备案名称
```

如果确实要改名，需要**先变更备案信息、更新软著，再提交上架**。

> 同理，**`bundleName` 定了就不要改** —— 它和 APP 备案、软著登记名称强绑定。

## 四、签名体系（和 Android 差别很大）

鸿蒙生态**从开发阶段就要求申请开发者证书**，且：

- **调试阶段要在 AGC 做三件事**：申请调试证书、注册调试设备、申请调试 Profile，然后才能配置签名。
  设备白名单落在 **Profile（`.p7b`）** 里 —— 证书本身不绑设备，**「绑设备」的是 Profile + 注册设备列表**。
  白名单外的设备装不上调试包，报的是签名/权限类错误，很容易误判成构建问题。
- **发布时必须用发布证书 + 发布 Profile 重新签名后上传**，保证开发者可溯源。
  注意「发布」不是「把调试包换个地方传」—— 证书和 Profile 都要重新申请。
- 应用上架后平台还会做安全隐私检测、审核、代码签名、应用加密。

**发布证书的有效期由 AGC 固定给 3 年**（在 p12 里写 25 年也一样），
到期换证时 **APP 备案的公钥 / 指纹要同步更新**。一个账号的发布证书有配额（**3 个**），别乱试。

> 手动申请发布证书的完整步骤与坑 —— keytool 参数、**密码必须是加密格式**、
> **release 包装不上真机**（所以混淆本地验证不了）—— 见 [06](06-打包与签名工作流.md)。

> ⚠️ **换签名 = 清数据。** 见 [07](07-踩过的坑.md) 坑 4。

## 五、APP 备案（**硬性前置条件**）

### 法律依据

- 《工业和信息化部关于开展移动互联网应用程序备案工作的通知》（2023）
- 《中华人民共和国反电信网络诈骗法》第二十三条

备案主体是 APP 主办者。由网络接入服务提供者（如华为云）或分发平台代为履行备案手续，
最终由主办者所在省级通信管理局审核。

### 谁要备案

- **所有提供互联网信息服务的 App**，含小程序、快应用等分发形态；
- 同一款 App 有多个包名、或同时有应用和元服务，**所有包名都要备案**；
- 同一款 App 已在安卓/iOS 备案过，**新增鸿蒙平台要走「变更备案」**添加平台，而不是重新备案。

### 备案前要满足的资源要求

APP 主办者使用的域名、IP 地址等网络资源需符合《互联网域名管理办法》《互联网IP地址备案管理办法》等要求。
也就是说，**如果你的 App 有后端域名，域名本身要合规、要能对应上主体**。

### 流程

1. **准备材料**
   - 主体信息（个人：身份证；企业：营业执照、法人信息）
   - App 信息（名称、包名、平台、图标、功能描述）
   - 域名 / IP / 服务器信息
   - 负责人信息 + 手机号（用于工信部短信核验）
2. **提交备案申请**：从华为云代备案入口提交（App 由华为云接入时在华为云备案）。
3. **接入服务商初审**：华为审核资料完整性与真实性。
4. **提交至通信管理局**：主体负责人先后收到「华为通知短信」和「工信部短信验证码」。
5. **工信部短信核验（关键，别漏）**：必须由备案负责人到工信部网站完成短信核验，
   **未完成核验则申请不会进入管局终审**。
6. **管局终审**。
7. **下发备案号**。

### 没备案的后果

- **应用市场侧**：安装按钮置灰，提示「该应用因未完成 APP 备案，暂不提供下载」；
- **上架审核侧**：备案校验不通过，无法通过审核。

### 常见坑

1. 漏做工信部短信核验，备案卡在「已提交管局」状态很久。
2. 备案名称和应用上架名称、软著名称不一致。
3. 已有安卓备案却直接新增鸿蒙包名当新备案提交 —— 应走变更备案。
4. 个人主体备案时，域名持有者与备案主体不是同一个人。

## 六、资质清单

| 资质 | 是否必须 | 说明 |
| --- | --- | --- |
| APP 备案号 | **必须**（联网应用） | 见上一节 |
| 软件著作权 | 官方口径「视品类 / 非必选但建议」；实际审核常被要求 | 见下文 |
| 特殊行业资质 | 视品类 | 金融、医疗、直播、地图、票务等需企业资质 |
| 隐私政策 + 用户协议 | **必须** | 需可公网访问的链接 |
| 内容分级问卷 | **必须** | 年龄分级 |
| 第三方 SDK 清单 | **必须** | 需在隐私政策中逐一明示 |
| 个人开发者承诺函 | 个人开发者必须 | 官方提供模板 |

### 软件著作权

- 官方文档的措辞是「软件著作权证书为非必选资质，但建议您申请」；应用资质审核要求里对非游戏类应用标为「视品类」。
- 但**实际提交时经常被要求补交**，且很多应用商店（含其他厂商）在中国大陆上架都要求软著，
  因此**建议默认办理**。
- 三种可选形式（选一）：《计算机软件著作权登记证书》、《APP电子版权证书》、《软件著作权认证证书》。
- 普通软著登记免费，但周期约 **1~2 个月**；加急 / 电子版权认证为付费（数百到上千元），几天到十几天可出。
- **名称必须与商店应用名称、APP 备案名称一致。**
- 如果你是代理别人的版权，还需提供版权授权书。

## 七、个人开发者的硬性限制

| 限制 | 说明 |
| --- | --- |
| 华为账号一键登录 | **不支持** |
| 获取用户手机号 | **不支持** |
| 获取收货地址 | **不支持** |
| 获取年龄段（游戏类能力） | **不支持** |
| 商店展示名称 | 个人姓名（不是 App 名/公司名） |
| 特殊行业类目 | 基本无法上架（需企业资质） |
| 游戏类 | 基本无法上架（需版号，版号要企业主体） |

**登录场景下个人开发者可用**：**华为账号登录**、**静默登录**。

### 特殊行业资质（举例）

以下类目均需**企业主体 + 对应许可证**，个人开发者无法覆盖：

| 类目 | 典型资质 |
| --- | --- |
| 金融理财 / 股票基金 / 贷款 | 《金融许可证》或地方金融批文，部分需《增值电信业务经营许可证》 |
| 征信机构 | 人民银行省级分支行出具的备案证明或《个人征信业务经营许可证》 |
| 贵金属 / 黄金相关 | 人民银行备案 + 交易所会员资格 + 合作协议 |
| 医疗器械 / 药品销售 | 《互联网药品信息服务资格证书》、经营许可/备案凭证 |
| 融资担保 / 小额贷款 | 《融资担保业务经营许可证》《小额贷款公司经营许可证》等 |
| 直播、微短剧、互联网地图、营业性演出票务、手机话费充值 | 结合应用核心功能与主营业务场景综合判断，通常需企业资质 |
| 具有舆论属性或社会动员能力的产品 | 安全评估报告 + 全国互联网安全管理服务平台审批截图 |

### 游戏类（个人开发者基本不可行）

1. 软著三选一（同「软件著作权」一节）；
2. 《网络游戏出版物号（ISBN）核发单》或《关于同意出版运营移动网络游戏的批复》；
3. 若上传者不是版号批文中的运营单位，需提供运营单位的版号授权书；
4. 版署实名认证：在网络游戏防沉迷实名认证系统上与华为平台关联获取 bizID，并在 AGC 提交审核；
5. 游戏名称须与软著名称一致，登记号需可在中国版权保护中心查询。

**版号本身需要企业主体申请，所以游戏对个人开发者基本关闭。**

**资质文件格式要求**：原件拍照或彩色扫描，或加盖公章的复印件；必须在有效期内；
不可隔屏拍摄，边角完整、内容清晰（国徽不得遮挡）；色调背景一致、无反光；
水印只能一行且不遮挡重要信息；支持 JPG / PNG / BMP / PDF。

## 八、隐私合规（最容易被驳回的一块）

- 上架前需提供**可公网访问**的隐私政策，如实填写应用信息和隐私声明。
- **所有集成了第三方 SDK 的 App**，都要在隐私政策中逐一明示该 SDK 收集个人信息的目的、方式和范围，
  否则可能上架不通过。
- 权限申请必须与应用实际功能匹配，**不能超范围申请**。
- 不能在审核时用技术手段隐藏违规内容、上架后再开启。

---

## 九、上架步骤

1. **AGC 创建应用**：填写应用名称、包名（bundleName）、应用分类、默认语言。
2. **配置应用信息**：图标、截图、简介、隐私政策链接、权限说明、分发国家/地区、付费情况、内容分级问卷。
3. **上传软件包**：上传 **`.app`**（打包见 [06](06-打包与签名工作流.md)）。
4. **填写资质文件**：软著、备案号、行业资质（视品类）。
5. **提交审核**。
6. **审核通过后发布**：可全量发布，也可分阶段发布。

### 测试轨道

正式发布前可以先用测试轨道收集反馈：

- **邀请测试**：挑选特定用户群组，上传测试包并填写测试信息；
- **公开测试**：向 AppGallery 用户公开发布测试版本。

> **邀请测试还有一个技术用途**：release 构建（含混淆）**本地装不上**（见 [06](06-打包与签名工作流.md) 坑 F），
> 想验证混淆后的真实行为，**唯一途径就是走邀请测试**。

AGC 还提供接入自检、云测试、云调试，可以提前发现兼容性/性能问题，减少正式审核被驳回的概率。

## 十、审核与常见驳回原因

审核依据《华为应用市场审核指南》与《应用资质审核要求》，两者都在持续更新。
支持催审、1v1 专家沟通等服务。

**常见驳回（速查）**：

- APP 备案缺失，或备案名称与上架名称/软著名称不一致
- 软著缺失 / 名称不一致 / 登记号查不到
- 隐私政策链接打不开，或未明示第三方 SDK
- 权限申请与功能不匹配
- 应用截图、描述与实际功能不符
- 分阶段或隐藏式违规内容
- 资质文件格式不合规（隔屏拍摄、水印遮挡、过期）

## 十一、能力边界：什么时候仍然需要 Windows / macOS

不是所有事 CLI 都能替代：

- **图形化调试器**（断点、变量监视、性能分析器、UI 设计器）—— CLI 给不了，需要 DevEco Studio。
- **AGC 控制台操作** —— 建证书、建 Profile、配地图等按应用身份授权的服务，必须在网页控制台点。
  签名本身 CLI 能做，**但第一次要先去 AGC 把调试设备加上**（见 [06](06-打包与签名工作流.md) 签名坑 0）。
- **上架提交、隐私政策托管、APP 备案** —— 都是网页流程（就是这一篇）。
- **图形密集的验证** —— 模拟器不如真机。

## 十二、CI / Docker

- CI 里用 CLT 就够了，构建、签名、装包都能跑。
- 官方 FAQ 给了 Dockerfile 搭 CLT 流水线的做法：
  `FAQ/命令行工具/使用Dockerfile搭建Command_Line_Tools流水线/faqs-command-line-tool-27`
  （另有「无网络流水线搭建」一篇，适合离线环境）。
