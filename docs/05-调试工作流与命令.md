# 05 调试工作流与命令

**前提**：命令行路径下**没有图形化调试器**（断点、变量监视、性能分析器、UI 设计器都是 DevEco Studio 才有的）。
这一篇讲**替代手段**，以及调试中最容易卡住的那几个故障。

工具位置与版本 → [02](02-工具链与工具位置.md)。构建循环 → [04](04-开发工作流与命令.md)。

---

## 一、核心思路：日志是猜，`ui layout` 是看

| 目的 | 手段 |
| --- | --- |
| 看应用日志 | `hdc hilog`，按 tag/domain/级别过滤 |
| **日志落盘** | `devecocli log --device <serial> --bundle-name <包名> --follow > /tmp/app.log 2>&1 &` |
| **让 Agent「看见」屏幕** | `devecocli ui layout`（导出节点树：布局、坐标、节点 ID、文本） |
| 截图 | `devecocli ui screenshot` |
| 模拟点击/滑动/输入 | `devecocli ui click` / `ui swipe` / `ui text` |
| 崩溃栈解析 | `hstack`（CLT 自带） |
| 应用信息 / 是否为 debug 包 | `hdc shell bm dump -n <包名>` |
| 强制停进程 | `hdc shell aa force-stop <包名>` |
| 让应用等调试器 | `hdc shell aa appdebug -b <包名>` |
| 看可调试进程 | `hdc track-jpid`（只有带 debug 标签的应用可调） |
| 内存 / CPU / 服务 | `hidumper --mem <pid>`、`hidumper --cpuusage`、`hisysevent -l`（**`-l` 查历史**，`-r` 实时订阅；**没有 `-q`**） |
| 性能采样 | `hiperf record -p <pid>` |
| 端口转发（本机访问设备内服务） | `hdc fport tcp:8080 tcp:8080` |
| 文件互传 | `hdc file send <src> <dst>` / `hdc file recv <dst> <src>` |
| 静态检查 | `devecocli check lint`、`devecocli check arkts` |

> **`ui layout` + `ui screenshot` 这一组对 Agent 特别有价值**：它把「页面上现在显示什么」变成可读文本，
> 比翻日志直观得多。**日志是猜，`ui layout` 是看。**
>
> 截图自己抓（`devecocli ui screenshot`）、自己读（直接打开 PNG）。**没有那次读取，就不要断言图片里显示了什么。**

## 二、四个最常卡住的故障

### 1. `hdc shell` 挂住（命令不返回，`EXIT=124`）

**先别怀疑设备、参数或 USB 线** —— 链路是好的，挂的只是**会话**。一条命令卡住会毒死整个会话，
之后每条 `shell` / `file` 都排在它后面。而 `hdc list targets` 全程显示 `Connected`，`doctor` 也看不出来。

```bash
hdc reconnect <key>                # 只重置会话，最轻
hdc kill -r                        # 重启服务端，对真实卡死实测有效
hdc kill && sleep 2 && hdc start   # 等价于 kill -r，拆开写
```

> ⚠️ **hdc 的退出码会骗人** —— `hdc reconnect`（不带 key）、无设备时的 `hdc shell`、
> `hdc -t <不存在的设备>` **都返回 0**。判断设备能不能用**只能靠真实往返**：
> `hdc shell "echo <标记>"` 并核对输出。
>
> 长会话先 `bash scripts/dev.sh keepawake`；**别让两个 Agent / 终端同时压同一台设备**。

**完整证据链、触发规律、自动恢复封装见 [07](07-踩过的坑.md) 坑 1。**

### 2. 平板锁屏挡住 `aa start`（`10106102`）

```
10106102 The device screen is locked
```

**触发条件是锁屏、不是熄屏** —— 实测点亮屏幕后 `aa start` 依旧失败，所以「唤醒屏幕」没用。
而且**失败发生在应用启动之前**，应用侧 API 救不了。

```bash
bash scripts/dev.sh keepawake             # 覆盖自动熄屏，默认 24h
bash scripts/dev.sh keepawake-restore     # 收工还原
```

> 两个代价：**会话开始那次解锁仍然只能人工做**；`-r` 是「恢复默认」，
> **会连带清掉机器上原本就有的 `OverrideTimeout`**，收工前先记原值。
> 详见 [07](07-踩过的坑.md) 坑 3。

### 3. 日志没抓到

设备实测 `hilog -g` 给出 app / core / only_prerelease 各 **512.0K**、init **64.0K**。
**能留多久取决于日志量，不是固定时长** —— 别赌「应该还在」：

```bash
devecocli log --device <serial> --bundle-name <包名> --follow > /tmp/app.log 2>&1 &
```

**必须在应用活着的时候启动**这一条 —— 应用一旦重启，之前的日志就没了。
详见 [07](07-踩过的坑.md) 坑 7。

### 4. 热重载的 watch 忘了停

`devecocli run --hotreload` 是常驻进程，忘了停会让后续**每次构建一直等待**。

```bash
devecocli run --hotreload stop      # 或 bash scripts/dev.sh hotreload-stop
```

**别用 `kill` 猜进程名** —— CLI 自己提供了 stop 动作。详见 [07](07-踩过的坑.md) 坑 8。

## 三、UI 不刷新怎么查

ArkUI 是状态驱动，改了变量 UI 不动，**九成是状态装饰器的问题**，不是渲染问题。
按顺序排查：

1. 驱动这个 UI 的变量**加装饰器了吗**（`@State` / `@Prop` / `@Link` / …）？普通成员变量改了不触发渲染。
2. 改的是**嵌套对象的属性**吗？对象只加 `@State` 不够，要 `@Observed` + `@ObjectLink`。
3. `ForEach` 的 **key 函数**写对了吗？写成固定值或索引会让框架认为元素没变。
4. 变量类型在**装饰器支持范围内**吗？（`Function` 类型不允许）

装饰器语义、支持的类型、V1/V2 差异 → [03](03-工程结构与代码规范.md) 第四部分。

## 四、模拟器

CLT 26.0.0 自带 emulator，Linux 上可用：

```bash
devecocli emulator license accept                                    # 非交互环境先接受协议（先看 license view）
devecocli emulator image list --all
devecocli emulator image download --device-type tablet --os-version "HarmonyOS 6.1.1(24)"
devecocli emulator create mytab --device-type tablet --os-version "HarmonyOS 6.1.1(24)"
devecocli emulator start mytab --no-window
```

实测坑：

- **无图形环境必须加 `--no-window`**，不加会报 `The x11 environment is incompleted`。
  `--help` 原文：`--no-window … required on Linux hosts without a GUI`。**不需要起 Xvfb。**
- **镜像 API 版本必须 ≥ 应用的 `compatibleSdkVersion`**，否则装不上。
- 非默认屏幕尺寸用 `--screen "宽 高 dpi 英寸"`（720–3500 / 720–3500 / 240–640 / 3.5–9；折叠屏传两组值）。
  CLI 上 `--screen-profile <model>` 也在，但**底层 `Emulator` 二进制的 `-screenProfile` 旧镜像可能不认**
  —— 两者不是同一个接口，别混。
- 文档里出现的 `-delete` / `-force` / `-screenProfile` 这类**单横线**开关属于**底层 `Emulator` 二进制**，
  不是 `devecocli emulator` 的子命令。`devecocli emulator delete` 只有 `--path`，**没有** `--force`。
- **模拟器上地图渲染的文字会变实心色块**（不是缺字体），要带地图的截图只能用真机。

> **模拟器 ≠ 真机。** 图形密集的验证、地图、真实性能表现，都要在真机上判断。

## 五、联网子命令被代理静默搞坏

**凡联网的 `devecocli` 子命令**（`auth` / `signature` / `update` / `emulator image` / `create`）都套一层：

```bash
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY devecocli auth status
```

失败方式是**假装成功**：`devecocli auth status` 打印 `Not logged in` 且 **`EXIT=0`**，
看着像没登录，实际是代理拦住了。**`auth status` 不能用来判断登录状态**（除非先去掉代理）。

`docs search` / `docs read` 是本地离线文档，不受影响。
`scripts/dev.sh` 已默认剥掉代理（需要代理时设 `HDOS_KEEP_PROXY=1`）。
完整 A/B 证据见 [07](07-踩过的坑.md) 坑 2。
